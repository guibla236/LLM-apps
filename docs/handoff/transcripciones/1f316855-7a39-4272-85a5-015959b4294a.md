## [5] Usuario — 2026-03-01 02:25

Te hago una consulta: cargar un prompt de esta manera (cuando el modulo se importa) es una mala practica? Puede el servidor fallar de alguna forma por hacerlo? Hay una mejor alternativa?

### Copilot

Cargar un prompt a nivel de módulo leyendo de disco (ej. `SUMMARY_PROMPT = get_prompt("summary_prompt")` como variable global) tiene pros y contras. 

En general, **sí se considera una práctica mejorable en aplicaciones de backend modernas (como FastAPI)**, por estas razones:

1. **Fallo en arranque (Crash on Startup)**: Si el archivo `.md` no existe o no tiene permisos de lectura, todo el servidor o el componente fallará al arrancar durante el *import*. A menudo, es preferible que la aplicación arranque y arroje un error específico (como un HTTP 500) cuando la funcionalidad es solicitada, sin tumbar toda la API.

2. **Dificultad para el testing**: Bloquea o dificulta los tests unitarios. Como la lectura está forzada en tiempo de importación del módulo, tienes que asegurarte de que el contexto de los archivos esté perfecto antes de siquiera poder importar la función. 

3. **Inflexibilidad al modificar (Hot-reloading)**: Si cambias `summary_prompt.md` en disco mientras el servidor está encendido, el servidor no verá el cambio. Tendrás que reiniciar la aplicación completa, ya que los módulos solo se evalúan una vez.

### ¿Cuál es la mejor alternativa?

La alternativa recomendada es cargar el prompt **justo antes de usarlo** (si el archivo es pequeño, leer de disco es muy rápido), o bien aplicar un **patrón de caché retardado (lazy loading / memoization)**.

Aquí tienes un par de formas mejores:

**Alternativa 1: Leer el archivo local/directamente (Recomendado para prompts pequeños)**
Cambia la lógica y carga en el lugar donde lo usas:
```python
            # Call our existing LLM
            llm = get_llm()
            summary_prompt_text = get_prompt("summary_prompt")
            summary_response = await llm.ainvoke([
                SystemMessage(content=summary_prompt_text),
                ...
```
*Ventaja:* Siempre tendrás la versión más nueva del prompt si lo editas, y si falla no tumba el servidor, solo la petición del usuario.

**Alternativa 2: Usar caché de `functools.lru_cache` (Mejor rendimiento)**
Si los archivos de prompts son grandes o tienes muchos llamados y te preocupa el escaso microsegundo de I/O de disco.
En tu `utils.py` puedes hacer:
```python
from functools import lru_cache

@lru_cache(maxsize=10)
def get_prompt(prompt_name: str) -> str:
    try:
        with open(f"prompts/{prompt_name}.md", "r") as f:
            return f.read()
    except Exception:
        raise FileNotFoundError(f"Prompt file '{prompt_name}.md' not found.")
```
