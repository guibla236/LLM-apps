# Milestones to Create on GitHub

Each Milestone models an Azure DevOps **Epic** (grouping deliverable for PBIs) while also acting as a **Sprint** with a due date. GitHub simply calls them "Milestones".

## General Guidelines

- **Suggested cadence**: 1 week per milestone (4 weeks total). Adjust based on availability.
- **Milestone closure**: when all its Issues are closed.
- **Issue count**: balanced so the GitHub Projects board looks active without being cluttered.

### M4 — Search Optimization: Embedding, Chunking & Lexical Search ✅ (2026-08-16)

- **Description**: Replaces `all-minilm:22m` (384-dim) with `voyage-4-lite` (1024-dim) and varies chunking per EDA findings. Replaces local BM25 (125 MB, broken in production) with MongoDB Atlas Search.
- **Completed**: 2026-08-16. Winner: **P1 (voyage-4-lite, chunk 1000/100)** with gpt-5.6-luna judge.
- **Final results** (gpt-5.6-luna, vector_only):

| Metric | Baseline (all-minilm) | **P1 final (voyage-4-lite)** | Δ |
|--------|:-----------:|:------:|:------:|
| Correctness | 50.40% | **51.00%** | +0.6 |
| Faithfulness | **98.91%** | 98.38% | −0.53 |
| AnswerRelevancy | 96.14% | **95.86%** | −0.28 |
| ContextualPrecision | 60.33% | **69.40%** | +9.07 |
| ContextualRecall | 23.66% | **25.91%** | +2.25 |

- **Experiment matrix results** (all with gpt-5.6-luna):

| Variant | CP | CR |
|---------|:---:|:---:|
| Baseline (all-minilm, hybrid) | 64.54% | 22.20% |
| **P0** (no-chunk) | 64.01% | 23.92% |
| **P1** (1000/100) | **69.40%** | **25.91%** |
| P1 hybrid | 69.65% | 23.19% |
| P1 + expansion | 74.41% | 27.35% |

- **Key finding**: No classic precision/recall trade-off — P1 improves both CP and CR simultaneously (Chen et al. 2023 alignment hypothesis validated). Hybrid no longer contributes on average (overlaps with strong semantic retrieval).

### M6 — Cost-Optimized Hybrid Inference ✅ (2026-08-16 — benchmark complete)

- **Description**: Benchmarks 3 LLMs against M4's retrieval baseline across complexity buckets to determine the optimal generator. Generation-only metrics (retriever held constant from M4).
- **Completed**: 2026-08-16. Benchmark executed with 75 queries (25 per complexity bucket), 3 models, gpt-5.6-luna judge.
- **Final results** (75 queries, gpt-5.6-luna):

| Model | Correctness | Faithfulness | AnswerRelevancy | Gen. median | Cost/1K (output) |
|-------|:-----------:|:------------:|:---------------:|:-----------:|:-----------------:|
| **deepseek-v4-flash** (baseline) | **0.465** | 0.983 | **0.956** | 11.9s | $0.047 |
| ling-2.6-flash (0.1×) | 0.412 | **0.997** | 0.788 | 5.5s | $0.011 |
| gemini-3.5-flash-lite (3.3×) | 0.161 | 0.852 | 0.628 | 2.5s | $0.173 |

- **Key findings**:
  - DeepSeek confirmed as production generator. Global advantage (5.3 pts CP) is at the edge of judge noise (~5 pts), but clear in the long-bucket (8.4 pts).
  - Ling is on the Pareto frontier of cost-quality (no model dominates it in both dimensions). Faithfulness 0.995-0.999 makes it safe against hallucination.
  - Gemini sets the latency standard (P95 ~3s, max 4.1s) — demonstrates deepseek's long tail is a service characteristic, not a physical limit.
  - Router implementation deferred — insufficient benefit given current model cost.
- **Documentation**: Entry 4 written (ES). EN translation pending. Logs in `4/logs/` (14 files).
- **Definition of Done**:
  - ✅ 3 LLMs benchmarked against M4 retrieval baseline (75 queries × 3 models).
  - ✅ Latency and cost measured per model per bucket.
  - ✅ Recommendation documented: keep deepseek.
  - ⬜ Entry 4 EN translation pending.
  - ⬜ Model router NOT implemented (deferred — not justified by benchmark).

### M8 — Vector Backend Migration (Pinecone → MongoDB + Voyage AI) ⏳

## Notes

- **Inter-milestone dependencies**: M1 ← M0. M2 ← M1. M3 ← M2. M4 ← M2 (needs retrieval baseline). M5 runs parallel to M4/M6/M7. M6 ← M4 (needs working retrieval). M7 ← M4 + M6 (agent consumes optimized RAG; benchmarks and graph work in parallel). M8 ← M4 + M6 (measures backend delta, not retrieval fix). M9 ← M8.
- **Critical path to strong portfolio**: M4 (retrieval fix + production unblock) → M3 update (blog with good numbers) → M7 (agentic diagnosis). M5 (CI/CD) in parallel. M6 (benchmarks only, ~1.5 days) in parallel with M7. M8-M9 are infrastructure/refinement — deferred.
- **BM25 production blocker**: The local BM25 index grew to 125 MB with real data, exceeding Vercel's cold start timeout and RAM limits. Hybrid search still adds retrieval value (ContextualPrecision 31.88% vs 29.37% vector-only) but is not deployable as-is. M4 resolves this via MongoDB Atlas Search (issue `04_MongoDB_Lexical_Search.md`). M8 later consolidates both lexical AND vector search under MongoDB.
- **Common blockers**: OpenRouter rate limit (embeddings + judge LLM). Pinecone 100K vector limit (namespace rotation). Voyage AI rate limit in M8 ingestion. Estimated total cost: <$15 across all milestones.
- **If a bug appears**: use `type:bug` label + active milestone. Do not create a new milestone.
- **Evaluation strategy**: M2 (data migration delta, fixed prompts). M4 (embedding + chunking + lexical search delta). M6 (cost model delta). M7 (agentic reasoning delta). M8 (backend migration delta). Each milestone changes ONE variable. All automated post-M5.
